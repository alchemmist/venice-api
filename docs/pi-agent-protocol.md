# Pi text-function adapter (v1)

The bridge translates declared OpenAI function tools and ordered messages into a
strict JSON-envelope prompt in the **existing Venice browser**, not Venice's paid
API. It never runs tools on the bridge: Pi executes them locally under its own
permissions. Venice's native instructions still exist; this is a prompt adapter,
not native system/tool API support. The inspected composer exposed model,
attachment and dictation controls, no verified disable-native-tools switch.

## Supported contract

- Text function tools with JSON Schema arguments; one call per assistant turn.
  `parallel_tool_calls=true` permits parallelism but does not require multiple
  calls: the adapter deliberately emits only one. `auto`, `none`, `required` and
  named function choice are enforced on the complete assistant envelope.
- Full ordered system/developer/user/assistant/tool history, null assistant
  content with tool calls, tool IDs and error output. Historical multiple calls
  and consecutive matching results are preserved. IDs are generated by bridge;
  duplicate IDs, missing/unmatched results are rejected. Execution/replay policy
  belongs to Pi; the bridge is not an exactly-once execution ledger.
- Argument validation without coercion, according to each declared schema
  (including additionalProperties when specified). External schema refs,
  custom/grammar tools and non-text content fail closed. This is NOT a full
  OpenAI API implementation. Sampling/max_tokens remain best-effort/unsupported
  browser semantics, unchanged from plain chat.
- The complete assistant source must be a raw v1 envelope, with no fences or
  extra prose. Only this rendered assistant component's pre-Markdown source is
  read: bounded React fiber traversal, exact Markdown props markers, identical
  duplicate sources, stop before parent message state. Missing/ambiguous props
  fail closed; there is no fallback to lossy DOM text. UI internal changes can
  break this path and require maintenance. No clipboard or raw network replay.
  No regex command extraction, Markdown unwrapping or automatic format repair.
  Malformed output produces HTTP502 / typed SSE error, never a tool invocation.
  Duplicate JSON keys and non-finite numbers are rejected.
- Non-stream returns JSON-string function arguments, bridge-generated call ID and
  finish_reason=tool_calls. Buffered SSE emits indexed delta.tool_calls only
  after validation, then tool_calls/[DONE]. Final text emits stop/[DONE].
- Conservative agent prompt budget: 120000 UTF-8 bytes including tool schemas;
  envelope: 65536 bytes. These are adapter safety budgets, not proven model
  context/output limits. Compact Pi history before reaching this budget.
- Existing one-generation browser lock, queue capacity4/wait180s, authentication,
  model selection, cancellation and plain chat path are retained.

## Verification

`python -m unittest discover -s tests -v` covers adapter validation, replay,
choice, SSE and all original browser/queue contracts (25 tests at first patch).

16 November 2026 pre-release PoC used an isolated localhost adapter routing text
through the unchanged production browser. Real Pi1.5.2, openai-completions,
buffered SSE: read calc.py, read test_calc.py, bash python3 -m unittest -v
(exit1), edit subtraction to addition, bash again (exit0), final report.
The fixture and real Pi event log are private controller evidence under
/tmp/venice-agent-poc; not a claim of LiteLLM acceptance or extended soak.
No production user chat was replayed; no Mac Chrome profile was touched.

Do not recommend unattended hours based only on this smoke test. Still verify
post-release LiteLLM round trip, fresh sessions, cancellation, ordinary WebUI
upstream, and bounded longer runs. Prompt injection and native Venice instruction
conflicts cannot be eliminated by envelope validation: local Pi permissions and
review are the authority. LiteLLM's existing prompt logging remains enabled.


## Transport defect found in the first bounded run

The first public 12-read run exposed a critical Markdown transport limitation:
raw JSON prose lost backslashes before quotes in a write argument containing
nested JSON. Validation rejected it; no write occurred. Pi automatically retried
model errors (distinct from bridge retries), then stopped after repeated failures.
One independent Venice navigation timeout also occurred before a prompt was sent.
Do not describe that initial run as successful soak or exactly-once reliability.

An intermediate fenced-code transport preserved escapes but triggered native
Venice tool processing (`Tool not found`); it FAILED real Pi acceptance. Inline
code also failed with delimiter collisions/native actions. Neither is accepted.

The final candidate reads the exact source string from this assistant's React
Markdown component before rendering. It requires raw JSON, no fences, and uses
an external envelope namespace:

{"pi_bridge":1,"action":"invoke","target":"read","payload":{"path":"fixture.txt"}}
{"pi_bridge":1,"action":"answer","text":"final Markdown report"}

The final source-based pre-release PoC passed seven real Pi calls with zero model
errors: two reads, failing unittest, edit, passing unittest, write a JSON fixture
with quotes/backslashes/newline, read back, complete final Markdown report. This
is not yet extended-soak evidence. The failed intermediate releases are retained
here deliberately rather than described as successful acceptance.
