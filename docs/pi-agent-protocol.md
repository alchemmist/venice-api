# Pi text-function adapter (v1)

The bridge translates declared OpenAI function tools and ordered messages into a
strict JSON-envelope prompt in the **existing Venice browser**, not Venice's paid
API. It never runs tools on the bridge: Pi executes them locally under its own
permissions. The browser uses Classic Chat and its `/api/inference/chat` text operation,
with explicit model/system prompt and disabled native web features. Neither
`/agents/venice` nor `/agents/ad-hoc` is allowed. Pi tool schemas remain EXTERNAL transcript data, not Venice tools.
No tokens are extracted and no official paid API client is used. See the README's
text-only browser transport contract and its fail-closed schema dependency.

## Supported contract

- Text function tools with JSON Schema arguments; one call per assistant turn.
  `parallel_tool_calls=true` permits parallelism but does not require multiple
  calls: the adapter deliberately emits only one. `auto`, `none`, `required` and
  named function choice are enforced on the complete assistant envelope.
- Full ordered system/developer/user/assistant/tool history, null assistant
  content with tool calls, tool IDs and error output. Historical multiple calls
  and consecutive matching results are preserved. IDs are generated by bridge;
  duplicate IDs, missing/unmatched results are rejected. Execution/replay policy
  belongs to Pi; the bridge is not an exactly-once execution ledger.
- Argument validation without coercion, according to each declared schema
  (including additionalProperties when specified). External schema refs,
  custom/grammar tools and non-text content fail closed. This is NOT a full
  OpenAI API implementation. Sampling/max_tokens remain best-effort/unsupported
  browser semantics, unchanged from plain chat.
- The complete assistant source must be a raw v1 envelope, with no fences or
  extra prose. Only this rendered assistant component's pre-Markdown source is
  read from the nearest bound assistant message, before math/Markdown transforms:
  bounded committed-tree identity lookup (50000 nodes,2048 root depth), at most48
  local ancestors, strict assistant role/nonempty ID/string content, no history
  contents, Markdown fallback or network replay. Unknown shapes fail closed.
  Both plain/compaction and structured completions use this exact raw source.
  No regex command extraction, Markdown unwrapping or automatic format repair.
  Malformed output produces HTTP502 / typed SSE error, never a tool invocation.
  Duplicate JSON keys and non-finite numbers are rejected.
- Non-stream returns JSON-string function arguments, bridge-generated call ID and
  finish_reason=tool_calls. Buffered SSE emits indexed delta.tool_calls only
  after validation, then tool_calls/[DONE]. Final text emits stop/[DONE].
- Agent SSE includes the existing approximate character-count usage estimate on
  the finish chunk so Pi can track context and initiate compaction. This is NOT
  native token/credit accounting; compaction accuracy and hours-long operation
  remain unproven. The hard prompt budget is still enforced.
- Conservative agent prompt budget: 120000 UTF-8 bytes including tool schemas;
  envelope: 65536 bytes. These are adapter safety budgets, not proven model
  context/output limits. Compact Pi history before reaching this budget.
- Existing one-generation browser lock, queue capacity4/wait180s, authentication,
  model selection and cancellation are retained. Plain chat and compaction use
  the same isolated text transport, with non-JSON system instructions.

## Verification

`python -m unittest discover -s tests -v` covers adapter validation, replay,
choice, SSE and all original browser/queue contracts (25 tests at first patch).

16 November 2026 pre-release PoC used an isolated localhost adapter routing text
through the unchanged production browser. Real Pi1.5.2, openai-completions,
buffered SSE: read calc.py, read test_calc.py, bash python3 -m unittest -v
(exit1), edit subtraction to addition, bash again (exit0), final report.
The fixture and real Pi event log are private controller evidence under
/tmp/venice-agent-poc; not a claim of LiteLLM acceptance or extended soak.
No production user chat was replayed; no Mac Chrome profile was touched.

Do not recommend unattended hours based only on this smoke test. Still verify
post-release LiteLLM round trip, fresh sessions, cancellation, ordinary WebUI
upstream, and bounded longer runs. Prompt injection and native Venice instruction
conflicts cannot be eliminated by envelope validation: local Pi permissions and
review are the authority. LiteLLM's existing prompt logging remains enabled.


## Transport defect found in the first bounded run

The first public 12-read run exposed a critical Markdown transport limitation:
raw JSON prose lost backslashes before quotes in a write argument containing
nested JSON. Validation rejected it; no write occurred. Pi automatically retried
model errors (distinct from bridge retries), then stopped after repeated failures.
One independent Venice navigation timeout also occurred before a prompt was sent.
Do not describe that initial run as successful soak or exactly-once reliability.

An intermediate fenced-code transport preserved escapes but triggered native
Venice tool processing (`Tool not found`); it FAILED real Pi acceptance. Inline
code also failed with delimiter collisions/native actions. Neither is accepted.

The final candidate reads the exact source string from this assistant's React
Markdown component before rendering. It requires raw JSON, no fences, and uses
an external envelope namespace:

{"pi_bridge":1,"action":"invoke","target":"read","payload":{"path":"fixture.txt"}}
{"pi_bridge":1,"action":"answer","text":"final Markdown report"}

The final source-based pre-release PoC passed seven real Pi calls with zero model
errors: two reads, failing unittest, edit, passing unittest, write a JSON fixture
with quotes/backslashes/newline, read back, complete final Markdown report. This
is not yet extended-soak evidence. The failed intermediate releases are retained
here deliberately rather than described as successful acceptance.


## Hardening: explicit history and budget policies

The root [README](../README.md) is the environment/build contract. The bridge image
no longer sets COOKIES_FILE; import is explicit standalone-only, never implicit
from the owner's home. Standalone profiles default outside the checkout under
XDG_DATA_HOME or ~/.local/share; existing profiles are not moved/deleted. Production
Chrome's PVC/CDP path and operator/egress secret wiring are unchanged.

Incoming history now checks function-call shape, nonempty names/IDs, argument
JSON objects, role placement, non-null non-assistant content and matching ordered
results. Assistant text plus tool calls is legal. Historical arguments are checked
against current schemas, but mismatches/removed tools are annotated in
history_validation rather than rejected: an errored attempt or a changed schema
must remain replayable. New calls still must satisfy current declarations and
schema. No historical call is executed by this adapter.

Recursive duplicate-key and nonfinite checks also cover scientific overflow
(1e999), and native nonfinite values in schema/message extras. Over-budget agent
requests return a typed OpenAI HTTP400 context_length_exceeded before browser
submission or SSE headers, with safe byte accounting and largest-message indices/
roles/sizes. No text/paths/arguments/IDs are echoed and no results are silently
trimmed. Schema overhead that cannot fit even with empty history gets distinct
reduce-enabled-tools guidance. This is an adapter byte budget, not a model token
limit. Synthetic boundary, Unicode, history-error replay and privacy tests cover
these behaviors.

The shared .dockerignore is an explicit default-deny context allowlist. CI audits
it using real BuildKit against ONLY staged runtime files and synthetic private
canaries, then checks bridge imports in the published image before GitOps deploy.
The operator's real profile/debug files are never staged by that audit.

## Native agent isolation regression

The `/agents/venice` AND `/agents/ad-hoc` runtimes can internally interpret
external JSON tool envelopes and attempt host tool names. Empty `tools` and
`clientTools` did NOT disable the ad-hoc detector: a real replay of the nightly
prompt produced `veniceai:tool_call_generation.in_progress` events with detected
`Unrecognized` bash/read tools, repeated internal model turns and a false final
report. Those were not Pi toolResult events. The earlier short acceptance did
not expose this and must not be cited as proof of complete isolation.

All completions now use the actual Classic Chat composer and the non-agent
`/api/inference/chat` endpoint. The browser consumes its normal NDJSON response;
the bridge still reads exact assistant DOM/React source, not network replay.
Canonical payload disables Venice system prompt/web search/scraping/X search,
retains only the latest exact user text (optionally stripping the verified UI
`/think ` prefix), explicit model/system instructions and request ID. No host
history is trimmed. All agent endpoints and unexpected inference POSTs fail
closed. No native fallback, automatic JSON repair or hidden retry is introduced.

Tests cover canonical payload and flags, agent-path rejection, history removal,
known prefix and unknown text transformations, wrong origin, repeated POSTs,
plain/compaction instructions, cancellation cleanup and explicit error semantics.
Live acceptance must reproduce the exact long nightly prompt in ordinary Pi,
with actual checkpoint files and tests, rather than synthetic reads alone.

## Classic dollar-sign regression

The first exact nightly prompt after Classic rollout exposed another real defect.
Network replies were valid envelopes, but Classic's pre-Markdown math processor
changed `$?` and `${PIPESTATUS[0]}` into invalid JSON escapes `\$`. The earlier
Markdown-props extractor therefore was NOT lossless on Classic. Reading this
current assistant's original message content fixes the source boundary, without
unescaping, JSON repair or modifying the model output. On the captured actual
night request, four browser replays produced two invalid old-extractor envelopes
and zero invalid raw-message envelopes. No tools were executed in those replays.
The matching browser request must finish before any response is released; failed
requests have explicit transport errors and all listeners/routes are removed.

## Browser lifecycle and probes

A subsequent actual nightly run exposed TWO real Chrome OOM kills at its existing
3Gi limit (Chrome exit137, bridge zero restarts), causing TargetClosed/API500s.
Do not attribute those errors to Pi's tool registry or hide them as normal output.
The exact allocator/leak cause was not established. To bound renderer retention,
NEW_CHAT_PER_REQUEST now replaces only the bridge-owned authenticated PAGE before
each request, rather than navigating the same tab indefinitely. The persistent
context, profile, cookies, Google identity and PVC are retained. Unknown-auth/MFA
pages are not discarded by this policy; no browser-memory limit was increased.

Health probes never launch or close a shared transport. A busy probe returns the
last known authenticated state without touching a navigating document. Idle probes
hold the same lock and have a 2s timeout; failed snapshots return503, without
tearing down an active Playwright driver. Dead-handle cleanup in login maintenance
also stays INSIDE that lock. These changes require runtime memory/restart soak
acceptance; passing unit tests alone is not an overnight reliability certificate.
